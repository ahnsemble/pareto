# Browser Fixtures

Deterministic wasm-bindgen browser fixture inputs and expected outputs generated by Codex for E-PARETO-WASM-NUMERICAL-EDGE-CASE-BATTERY-V1. Each `browser_*.json` file contains `exportName`, `args`, and `expected` fields. Outputs are normalized from `serde-wasm-bindgen` Maps into plain JSON objects by `tests/numerical_battery/wasm_bridge.mjs`.

- Fixture count: 60
- Categories: decode_public_raw, make_synthetic_search_space, run_full_pipeline, merge_stat_dicts
- Browser aggregate caveat: fixture-backed filesystem fallbacks are unavailable in the WASM/browser build, so run_full_pipeline fixture cases currently expect empty stats instead of native fixture stats.

## Browser Fixture Seed Data Preservation Rule

- Do not delete seed data under `tttg_forge_wasm/tests/browser_fixtures/` during feature work.
- When a fixture behavior must change, add a new `_v2` fixture group or new numbered fixture and keep the Sprint G.3 seed set intact.
- Fixture deletion is reserved for an explicit cleanup sprint with a manifest diff and battery-count update in the report.
- The manifest `fixtureCount` must stay at or above the Sprint G.3 baseline of 60 unless that cleanup sprint approves a lower count.
